### StoryWeaver AI — 설정 조회와 독립 검수

Python 노트북의 LangChain 설계를 Next.js 웹 서비스로 확장한 개인 프로젝트입니다.

- 캐릭터·세계관·관계·필연·이전 장면과 역사 정보를 6개 Tool로 조회하도록 설계했습니다.
- 작가 Agent의 초안을 검수 Agent가 원본 설정과 대조하고, 최종 장면만 프로젝트 상태에 반영합니다.
- Pydantic·Zod로 대사와 사건·관계 변화를 구조화하고, 모델 호출 실패에는 재시도 Middleware를 적용했습니다.
- 브라우저에 장면을 저장하고 이전 사건을 다음 생성에 연결합니다. 벡터 RAG가 아닌 구조화된 레코드 조회 방식입니다.

### ReviQ — 보고서 생성과 후속 대화 분리

초기 Catchy 팀 프로젝트에서 AI·데이터 부분을 담당한 뒤, 본인이 개발한 AI를 바탕으로 웹 버전을 혼자 확장했습니다.

- Excel·CSV 업로드부터 CrewAI의 정량 분석 → 원인 추적 → 보고서 작성까지 연결했습니다.
- 후속 질문은 저장된 보고서와 선택한 원문을 한 번의 모델 호출로 참고하며, 매번 3단계 분석을 반복하지 않습니다.
- 원문 해시와 보고서 버전을 확인하고 자료가 바뀌면 보고서를 갱신합니다. 실패·취소·시간 초과와 미완성 결과도 구분합니다.
- Next.js 화면, FastAPI 분석 서버, IndexedDB 저장과 보고서 내보내기를 구현했습니다. 원인·위험도·손실액은 별도 운영 데이터 검증이 필요한 AI 추정입니다.

### NYC Taxi Fare Pipeline — OOF 특징 설계와 오차 진단

팀원이 설계한 시간·공간·빈도 특징에 OOF 타깃 인코딩을 결합한 본인 모델이 팀 최종안으로 채택됐습니다.

- 약 1만 9천 개 노선 조합에 해당 행의 Fold를 제외한 그룹 요금 통계를 적용하고 희소 그룹에는 평활화를 사용했습니다.
- 날짜 기준 학습·테스트 분리 평가에서 제출 보고서 기준 MAE **$2.6978**, R² **0.9057**, ±$5 이내 예측 비율 **85.89%**를 기록했습니다.
- 요금제별 오차와 특징 중요도로 후속 개선 대상을 정리했습니다. 별도 실행 산출물의 지표는 제출 성과와 구분합니다.
- 실제 운행거리 기반 오프라인 평가이므로 출발 전 적용에는 예상 거리로 재평가가 필요하며, Fold별 평활화 기준값 분리도 남은 개선점입니다.

## How I Work

- **Problem Framing:** AION의 분석 단위를 단일 플로우에서 5초 통계 트래픽으로 다시 정의했습니다.
- **Reliable AI:** LLM이 서비스 DB와 최신 외부 데이터 안에서 답하도록 컨텍스트와 제약을 설계합니다.
- **Agent Workflow:** StoryWeaver는 작성·검수를, ReviQ는 3단계 분석과 후속 대화를 분리해 작업 목적에 맞는 실행 흐름을 설계했습니다.
- **Reproducible ML:** 데이터 누수 방지, 베이스라인 비교, 오분류 분석과 재현 가능한 파이프라인을 중요하게 생각합니다.
- **Product Iteration:** 공모전 발표에 머무르지 않고 실제 배포와 사용자 피드백을 다음 개발 우선순위로 연결합니다.
